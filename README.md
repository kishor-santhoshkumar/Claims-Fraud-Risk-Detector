# Claims Fraud Risk Detector

A hackathon project for US payer claims / payment integrity fraud detection. The system predicts whether a healthcare **provider** is fraudulent using the Kaggle ["Healthcare Provider Fraud Detection Analysis"](https://www.kaggle.com/datasets/rohitrox/healthcare-provider-fraud-detection-analysis) dataset. The unit of prediction is the provider, not the individual claim.

## Overview

The dataset provides three claim tables (beneficiary demographics, inpatient claims, outpatient claims) and a provider-level fraud label. All three claim tables are joined, enriched with per-claim derived fields, and aggregated to produce a 31-feature provider-level matrix. A two-stage cascade classifier (RandomForest gate + XGBoost ranker) is then trained on that matrix.

Download the dataset from Kaggle and place all four `Train_*.csv` files in the `data/` directory. The loaders use glob patterns so the exact timestamp suffixes in the filenames do not matter.

## How to Run

```bash
jupyter notebook notebooks/01_fraud_analysis.ipynb
```

Run all cells in order. The notebook covers:

1. EDA and class balance analysis
2. Claim-level enrichment via `src/loaders.py` and `src/features.py`
3. Cross-entity ring signal computation
4. Provider-level feature aggregation (cached to `outputs/features_train.parquet` after the first run — subsequent runs load from cache)
5. Two-stage model training with 5-fold cross-validation
6. SHAP analysis and expected-loss ranking

## Feature Engineering

All 31 features are computed at the provider level by aggregating across all inpatient and outpatient claims attributed to that provider.

| Group | Features |
|---|---|
| Volume | `n_claims`, `n_unique_bene`, `n_inpatient_claims`, `n_outpatient_claims`, `ip_op_ratio`, `claims_per_bene` |
| Physician | `n_unique_attending`, `n_unique_operating`, `n_unique_other`, `claims_per_physician` |
| Money | `total_reimbursed`, `mean_reimbursed`, `max_reimbursed`, `std_reimbursed`, `total_deductible`, `mean_deductible` |
| Duration | `mean_claim_duration`, `max_claim_duration`, `mean_admission_length`, `max_admission_length` |
| Coding | `mean_n_diag`, `mean_n_proc`, `n_unique_primary_diag`, `primary_diag_entropy` |
| Patient mix | `mean_chronic_count`, `mean_age_at_claim`, `deceased_rate` |
| Geography | `n_distinct_states`, `n_distinct_counties` |
| Cross-entity ring signals | `mean_phy_n_providers` (mean number of distinct providers an attending physician bills across), `mean_bene_n_providers` (mean number of distinct providers a beneficiary appears at) |

## Model Architecture

A two-stage cascade is used to handle class imbalance while maximising recall on fraudulent providers.

**Stage 1 — RandomForest gate**

Trained on the full provider matrix using out-of-bag (OOB) probabilities. Providers below the gate threshold are eliminated. The gate retains approximately 95.3% of fraudsters while discarding approximately 72% of the total provider population.

**Stage 2 — XGBoost ranker**

Trained on gate survivors only. `scale_pos_weight` is set from the class ratio of the surviving population. `eval_metric=aucpr` is used as the optimisation objective to focus on precision-recall trade-off rather than accuracy.

**Cross-validation**

`StratifiedKFold(n_splits=5)` applied on the provider-level matrix, stratified by `fraud_label`.

## Results

5-fold out-of-fold (OOF) evaluation on the provider-level training set:

| Run | PR-AUC | ROC-AUC | Recall@100 | Recall@500 |
|---|---|---|---|---|
| All 31 features | 0.728 | 0.942 | 18.6% | 65.4% |
| Volume features excluded | 0.730 | 0.940 | 18.8% | 65.6% |

Volume features (raw counts such as `n_claims`, `n_inpatient_claims`) add no lift over the ratio features (`claims_per_bene`, `ip_op_ratio`) that already capture the same signal in normalised form.

**Top 10 SHAP features (by mean absolute SHAP value)**

1. `total_reimbursed`
2. `max_admission_length`
3. `claims_per_bene`
4. `total_deductible`
5. `max_claim_duration`
6. `mean_chronic_count`
7. `mean_bene_n_providers` (cross-entity ring signal)
8. `deceased_rate`
9. `mean_age_at_claim`
10. `n_distinct_states`

**Expected-loss ranking**

Providers are ranked by `fraud_probability * total_reimbursed`. The top 20 by expected loss are all confirmed fraudsters, with the highest-ranked entry carrying approximately $6M in expected loss.

## Data Encoding Notes

Several non-obvious encoding issues in the raw CSVs are corrected in `src/loaders.py`. Mishandling any of these will silently produce wrong feature values.

| Column | Raw encoding | Corrected to |
|---|---|---|
| `RenalDiseaseIndicator` | Mixed `'0'` / `'Y'` strings | `0` / `1` integer |
| `ChronicCond_*` (11 columns, including the misspelled `ChronicCond_Osteoporasis`) | `1` = Yes, `2` = No | `1` / `0` integer |
| `DOD` (date of death) | Literal string `'NA'` not treated as missing by default | Converted to `NaT` via `na_values=['NA']` |
| `State`, `County` | Numeric-looking codes that are categorical identifiers | Loaded as `str`, never cast to `int` |
| `BeneID`, `ClaimID`, `Provider` | String identifiers | Loaded as `str` to prevent implicit numeric coercion |
| All `*Dt` columns | Date strings | Parsed as `datetime64` with `date_format='%Y-%m-%d'` |

## Known Limitations

**Cross-entity data leak (mild)**

The `mean_phy_n_providers` and `mean_bene_n_providers` ring signals in `src/features.py` (`compute_cross_entity_spans`) are computed over the full concatenated dataset before the train/validation split inside cross-validation. This means the CV metric is slightly optimistic for these two features because a validation-fold provider's patients and physicians have already been seen when computing the span counts. This is flagged in the notebook. The leak is mild in practice because the spans aggregate across many records, but it should be corrected before deploying to a production evaluation pipeline by computing spans on the training fold only and joining them onto the held-out fold.
